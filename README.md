# BloodBank AI — Multi-Blood-Bank Demand Forecasting & Stock Status Prediction

A Streamlit academic project rebuilt around the supplied `Untitled8.ipynb` Random Forest classification workflow and `blood_bank_demand_shortage_2024_2026.csv` dataset.

## What the application does

- Multi-bank demo login (one super admin and five blood-bank accounts)
- Dashboard with latest stock-status distribution, demand trends and inventory snapshot
- Stock-status prediction with five classes: `Adequate`, `Surplus`, `Low`, `Critical`, `Shortage`
- Demand forecasting for 7, 14 or 30 days by bank and blood group
- Blood-bank network comparison
- Dataset explorer with filters and CSV export
- Model evaluation: accuracy, weighted F1, per-class precision/recall/F1 and confusion matrix
- Downloadable reports

## Models

### 1. Stock-status classifier

The notebook uses a `RandomForestClassifier` with 100 trees and `random_state=42`. This project keeps that core model and adds a preprocessing pipeline so categorical fields are encoded consistently during both training and prediction.

Target: `stock_status`

Five classes:
- Adequate
- Surplus
- Low
- Critical
- Shortage

The supplied notebook selects the last column when it does not find a target column by name. In the supplied CSV, the last column is `stock_status`.

**Prediction-time feature handling:** fields that describe outcomes after the prediction point are excluded: `units_issued`, `unmet_demand_units`, `expired_units`, `closing_stock_units`, and `stock_days_estimate`. This avoids using information that may not be available when making a forward-looking estimate. The classifier uses the opening stock, donations, demand/request information, bank, blood group, donor camp and weather/calendar context.

Evaluation uses an 80/20 random train/test split with `random_state=42`, following the notebook. Metrics are generated by the application or `train_models.py`; they are not hard-coded.

### 2. Demand forecasting model

The notebook does not train a demand regressor. To retain the project's demand-forecasting feature, a separate `RandomForestRegressor` is trained using the supplied dataset's `total_demand_units` history. Features include bank, blood group, calendar variables, previous-day demand, seven-day lag, and rolling 7-/30-day averages.

The demand model uses a chronological 80/20 holdout for MAE and RMSE evaluation. Forecasts are generated recursively, so later forecast days use earlier predictions as lag inputs.

## Dataset

File: `dataset/blood_bank_demand_shortage_2024_2026.csv`

The supplied CSV contains 30,480 rows and 25 columns, covering 2024-01-01 through 2026-01-31, with five blood banks in West Bengal. It includes daily stock, donations, demand, request categories, weather/calendar context and stock-status labels.

The data is treated as the project dataset. It is not represented as verified live blood-bank data.

## Operational interfaces retained from the previous project
The rebuilt app keeps the previous project navigation pages: Dashboard, Inventory, Record Donation, Blood Requests, Demand Forecasting, Shortage Prediction, Blood Bank Network, and Reports. It also retains the newer Dataset Explorer and Model Performance pages. Inventory starts from the latest available snapshot in the supplied CSV. Donation and request actions update a separate local SQLite demonstration ledger (`database/operations.db`); they do not alter the historical CSV used to train/evaluate the models.

## Run on Windows

1. Extract the project ZIP.
2. Open the `BloodBank-AI` folder in VS Code.
3. Open PowerShell in that folder.
4. Create and activate a virtual environment:

```powershell
python -m venv venv
venv\Scripts\activate
```

5. Install dependencies:

```powershell
pip install -r requirements.txt
```

6. (Recommended) Train both models:

```powershell
python train_models.py
```

7. Start the application:

```powershell
streamlit run app.py
```

The app opens at `http://localhost:8501`. On first use, it also trains a missing model automatically.

## Limitations and responsible use

This is an educational prototype. The dataset and model outputs must not be used for clinical decisions, blood compatibility decisions, transfusion, inventory release, or emergency allocation. Actual stock status and availability must be verified by authorized blood-bank professionals. Model performance on this dataset does not establish real-world reliability.
